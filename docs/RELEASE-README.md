# Rebuilt resctl-bench runtime - reviewed native compatibility repair

This runtime is generated by build kit 2.4.0 from the repaired supplied 2.2.6
source. It embeds the BCC/Python correction so rd-agent reset cannot restore the
old collector. Native Btrfs device lookup uses JSON and no filesystem suffix.
It is a downstream local patch, not an unmodified official release.

From this runtime directory:

```sh
sha256sum -c SHA256SUMS
python3 -I -B install.py --package . --verify
python3 -I -B runtime_support.py
```

The last command executes the real rd-agent's file-only support exporter and
compares all five helpers with the reviewed contract. It does not run a normal
agent, invoke systemd, change swap, attach BPF or start a workload.

An optional, explicitly requested real BPF initialization check is:

```sh
sudo /usr/bin/python3 -I -B runtime_support.py --probe-latency nvme0n1
```

Use the actual selected whole disk, not a partition, zram or mapper. This command
attaches BPF temporarily but does not start a disk workload. Read the runtime
guide for prerequisites and limits. Probe errors are not converted to success.

`bin/` contains resctl-bench, rd-agent, rd-hashd and optionally resctl-demo.
`bin/.debug/` contains selected split debug files. `share/resctl-bench/build/`
contains compiler/build logs, exact inputs and flags, locks, ELF data, native
regression results, patches and the compiled-support verification. Licenses
and the dependency inventory are under `share/licenses/resctl-bench/`.

Native CPU tuning is not portable to arbitrary hardware. These executables
are dynamically linked; inspect the ELF/build information and use compatible
runtime libraries. A successful build is not a completed physical benchmark.

IOCost Lab 2.1 uses a root-owned installation of all three native binaries.
The matched source bridge detects --bin-dir; it does not give a user-writable
build stage to a privileged Lab. Use the Lab's doctor to verify the compiled
`resctl-iocost-lab-v3` contract after installing the complete trio.

Install to /usr/local after reviewing conflicts:

```sh
sudo /usr/bin/python3 -I -B install.py --package . --prefix /usr/local
```

Use --destdir for staging. Conflicts and modified tracked files are refused by
default; --uninstall removes tracked unchanged files. Installation does not
start a benchmark or install measured IOCost parameters. Those are separate
Lab deployment actions after a successful benchmark and restoration.

Native v3 uses exact native-owned balloon allocation and checked lifecycle transitions. Use IOCost Lab 2.5.0; restore old tracked sessions before a new calibration. The source delivery did not execute native compilation or physical benchmarking; consult the build evidence actually generated on your host.
